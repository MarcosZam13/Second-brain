# Enterprise-Level UI/UX Design

The standard: design that reads as **intentional and specific to the product**, not template output. A reviewer (professor, interviewer, client) should be able to tell this wasn't generated by picking the first suggestion from an AI without any direction.

## 1. How to spot (and avoid) the "AI-generic" look

Common tells to actively avoid:
- Purple-to-blue gradients as a default background/accent with no reason tied to the brand.
- Overuse of glassmorphism/blur cards with no functional purpose.
- Generic rounded-everything with the same border-radius on every element regardless of hierarchy.
- Centered hero + 3 feature cards + testimonials, in that exact order, with no variation.
- Emoji used as icons instead of a proper icon set (already banned in Tacha's design, apply everywhere).
- Inter/system-ui as the only typeface with no pairing or personality.
- Uniform drop shadows on every card with identical values.

Counter-move: **every design decision should be traceable to something specific about the product** — the brand's personality (e.g. Tacha's "warm/homey" identity → Fraunces + Public Sans + terracotta, not a generic SaaS palette), the user's context (gym members mid-workout need large tap targets, not dense dashboards), or a real content hierarchy (not decoration for its own sake).

## 2. Process before pixels

1. **Define the personality in words first** (2-3 adjectives) before touching color or type. "Warm, trustworthy, unhurried" produces different decisions than "fast, technical, high-density."
2. **Establish hierarchy from content, not from a template.** What does the user need to see first? Second? What can be de-emphasized or removed entirely?
3. **Pick a distinctive anchor decision** — one deliberate choice that isn't the safe default (an unusual but legible type pairing, an asymmetric layout, a specific accent color with a reason) — and let the rest of the system support it consistently.

## 3. Foundations

**Typography**
- Pair a distinctive display/heading font with a highly legible body font — never rely on a single generic sans for everything.
- Establish a real type scale (not arbitrary sizes): consistent ratio between heading levels.
- Line length for body text: 45-75 characters for readability.

**Color**
- One primary, one secondary/accent, and a neutral scale — resist adding more without a reason.
- Check contrast ratios (WCAG AA minimum: 4.5:1 for body text, 3:1 for large text) — this isn't optional for anything meant to look professional.
- Both light AND dark mode get equal design attention, not dark mode as an inverted afterthought.

**Spacing & layout**
- Use a consistent spacing scale (e.g. 4px/8px base unit) — arbitrary padding values are what make layouts feel "off" without anyone knowing why.
- Group related elements with proximity; separate unrelated ones with real whitespace, not just a border.
- Grids should reflect actual content relationships, not just "3 columns because that's default."

**Icons**
- SVG outline icon sets, consistent stroke width across the whole set. Never emoji in a product UI.
- Icons support text, they don't replace it when clarity matters (an icon-only button needs a tooltip or label unless the icon is truly universal — trash, close, search).

## 4. Enterprise-level polish checklist

- **States are designed, not left to default:** hover, active, disabled, loading, empty, and error states all get explicit treatment — not just the happy path.
- **Empty states have purpose:** guide the user to the first action, don't just say "no data."
- **Feedback is immediate:** any action (save, delete, submit) gets visible confirmation — a toast, an inline state change, something.
- **Responsive isn't an afterthought:** design mobile and desktop as intentional layouts, not one squeezed into the other.
- **Motion has purpose:** transitions clarify what changed (a card expanding, a list reordering) — not decoration for its own sake. Keep durations short (150-300ms for UI feedback).

## 5. Applying this in practice

When asked to design or review a UI under this skill:
1. Ask (or infer from existing project context) the personality/brand adjectives before proposing colors or type.
2. Check the design against the "AI-generic" tells in section 1 — flag and replace any that show up.
3. Verify states (hover/empty/error/loading) are covered, not just the primary happy-path screen.
4. Check contrast ratios before calling a color palette final.
5. For an existing project (e.g. GymBase's `#080808` / `#FF5E14` / Barlow Condensed system, or Tacha's warm palette), stay consistent with its established system rather than introducing a new one — enterprise-level design means consistency across a product, not novelty per screen.
